**여기서 나온 두 가지 설계 결정:**

1. **임베딩 엔드포인트가 없으므로 검색은 BM25(어휘 검색) 기반으로 간다.** 벡터 검색을 1순위로 두면 키가 없을 때 아무것도 배포할 수 없다. BM25는 의존성 0, 시크릿 0, 콜드스타트 0이라 어디서든 동작한다. 문서 15개 규모에서는 성능도 충분하다. 임베딩은 시간이 남을 때 얹는 **선택적 강화**로 강등한다.

2. **`chat_template_kwargs: {"enable_thinking": false}` 를 반드시 넣어야 한다.** 안 넣으면 Qwen3가 reasoning 토큰만 태우다 `finish_reason: "length"` 로 끝나고 `content`가 빈 문자열로 온다. 실제로 재현했다. 이거 모르고 시작하면 1시간 날린다.

> ⚠️ Spark 엔드포인트는 **인증이 없다.** Vercel이 접근하게 하려고 Funnel/ngrok으로 노출시키지 말 것. Vercel 경로는 BYOK로 간다.

   Next.js 15 App Router (Vercel)                        │  /api/chat  (Node)        │

   │ · 신뢰도 배지             │                          │  5. OpenAI 호환 스트리밍    │
   │ · BYOK 키 입력 (localStorage)│                       └──────────┬────────────────┘
   └──────────────────────────┘                                      │ 동일한 클라이언트
                                                    ┌────────────────┴────────────────┐
                                                    ▼                                 ▼
                                       LLM_BASE_URL = Spark(온프레미스)     BYOK: api.openai.com
                                       Qwen3.8-Flash / 키 없음              사용자 키 / 서버 미저장

## 차별화 포인트 (심사 키워드 대응)

| 키워드 | 구현 |
|---|---|
| **RAG** | 청킹 → BM25 검색 → 근거 주입 → 인용 포함 생성. 검색된 청크를 UI에 그대로 노출 |
| **신뢰도** | ① 모든 답변에 `[출처: 문서명 §섹션]` 인용 강제 ② **임계값 미달 시 답변 거부** — "사내 문서에서 근거를 찾지 못했습니다"로 응답하고 담당 부서 안내 ③ 검색 점수를 UI에 그대로 표시 |
| **보안** | **문서 단위 접근 제어(RBAC).** 각 문서 frontmatter에 `access_role`. 검색 *이전에* 필터링하므로 권한 없는 문서는 LLM 컨텍스트에 **애초에 들어가지 않는다.** 같은 질문("연봉 테이블 알려줘")이 역할에 따라 다르게 답하는 데모 |
| **온프레미스** | 실제 GPU 서버(DGX Spark GB10 / sglang)로 추론하는 로컬 모드 + 구축 방안 설계 문서 |

RBAC 필터는 코드 20줄 남짓인데 데모 임팩트가 가장 크다. "권한 없는 문서는 컨텍스트에 안 들어간다"는 건 실제 엔터프라이즈 RAG의 1순위 과제다.

### 0:50–1:20 — 온프레미스 설계 문서 (30분) ★ 비협상

**의도적으로 앞으로 당겼다.** 주최 측이 명시적으로 요구한 필수 산출물인데 마지막에 두면 빌드가 밀릴 때 잘려나간다. 그리고 이건 **반드시 완성 가능한 유일한 산출물**이다.

`docs/on-premise-architecture.md` — 실제 측정값이 있어서 일반론 문서보다 훨씬 강하다:

1. **왜 온프레미스인가** — 사내 규정·인사 데이터의 외부 전송 리스크, 컴플라이언스
2. **참조 구현 (실측)** — DGX Spark GB10 + sglang + Qwen3.8-Flash-NVFP4, 262K 컨텍스트, Tailscale 사설망 격리, 실측 지연 시간, NVFP4 양자화 선택 근거
3. **모델 서빙** — sglang vs vLLM vs Ollama 비교표, 양자화(NVFP4/AWQ/GGUF) 트레이드오프
4. **임베딩 계층** — *이번 검증에서 드러난 실제 문제*: 추론 서버가 임베딩을 제공하지 않음 → bge-m3를 별도 컨테이너로 분리 서빙하는 구성. 실패에서 나온 설계라 설득력이 있다
5. **벡터 DB** — Qdrant / pgvector 비교, 현재 BM25에서 마이그레이션하는 경로
6. **하드웨어 사이징** — 100명/1000명 규모별 GPU·메모리·스토리지 산정
7. **네트워크·보안** — 외부 egress 차단, 사설망, 문서 단위 ACL을 벡터 DB 메타데이터 필터로 강제, 감사 로그, PII 마스킹
8. **배포 토폴로지** — docker-compose 구성도 (LLM / 임베딩 / 벡터DB / 앱)
9. **비용 비교** — 3년 TCO: 온프레미스 vs API 종량제 손익분기점
10. **운영** — 모델 업데이트, 인덱스 재구축, 모니터링, 백업

> PII 마스킹과 감사 로그는 **이 문서에서 설계만** 한다. 구현하지 않는다. (시간 예산상 컷)

- → `data/index.json` 출력 (15문서 × 4섹션 ≈ 60청크, 수백 KB)

### 2:00–2:45 — LLM 클라이언트 + /api/chat (45분)

**`lib/llm.ts`** — OpenAI 호환 클라이언트 하나. 프로바이더 분기는 설정값뿐:

```ts
// 온프레미스: baseURL=http://spark-f5e2.tail0bfda4.ts.net:8000/v1
//             model=Inferact/Qwen3.8-Flash-Next-NVFP4, apiKey='not-needed'
// BYOK:       baseURL=https://api.openai.com/v1
//             model=gpt-4o-mini, apiKey=요청 헤더에서
```

**반드시 지킬 것 (검증 완료된 함정):**
- 온프레미스 모델 호출 시 `chat_template_kwargs: { enable_thinking: false }` 를 body에 포함. 누락하면 빈 응답이 온다
- 스트리밍 시 `delta.reasoning_content`와 `delta.content`를 구분 처리. reasoning은 버린다
- `max_tokens` 최소 1024

**`app/api/chat/route.ts`** 흐름:
1. `{ message, role, history }` + `x-byok-key` 헤더 수신
2. `searchChunks(message, role)` 호출
3. **최고 점수 < 임계값 → LLM 호출 없이 즉시 거부 응답 반환** (근거 없으면 생성하지 않는다)
4. 근거 청크로 프롬프트 구성 — 시스템 프롬프트에 명시: *"제공된 문서에만 근거해 답하라. 문서에 없으면 모른다고 답하라. 모든 문장에 `[출처: 문서명 §섹션]` 형식으로 인용하라."*
5. 스트리밍 응답 + 근거 메타데이터를 헤더/첫 청크로 전달

**BYOK 보안 원칙:** 키는 요청 헤더로만 받고 **서버에 절대 저장/로깅하지 않는다.** 브라우저 localStorage에만 보관. README에 명시.

**완료 기준:** curl로 `/api/chat` 호출 시 인용이 포함된 한국어 답변이 스트리밍된다.

## 검증 방법

블록별 완료 기준은 위에 각각 적었고, 최종 E2E는 다음 순서로 확인한다:

1. **인제스트** — `pnpm tsx scripts/ingest.ts` → `data/index.json` 생성, 청크 수 60±20 확인
2. **검색 단독** — 노드 스크립트로 `searchChunks("연차 며칠", "all")` → 연차 규정이 1위
3. **RBAC** — `searchChunks("연봉 테이블", "all")` 결과에 HR-011 문서 **없음** / `role="hr"`에서는 **1위**
4. **거부 동작** — "오늘 점심 메뉴 뭐야?" → LLM 호출 없이 거부 응답 (네트워크 탭에서 확인)
5. **온프레미스 생성** — `LLM_BASE_URL=http://spark-f5e2.tail0bfda4.ts.net:8000/v1` 로 로컬 실행 → 인용 포함 한국어 답변. `reasoning_content`가 화면에 새지 않는지 확인
6. **BYOK 경로** — Vercel 배포본에서 키 입력 후 동일 질의 → 동일 동작
7. **배포본 스모크** — 예시 질문 칩 3개 클릭, 역할 3개 전환하며 답변 변화 확인
8. **보안** — 서버 로그에 BYOK 키가 찍히지 않는지 확인, `.env`가 `.gitignore`에 있는지 확인

## 시간이 부족할 때 자르는 순서

역순으로 자른다. 위쪽이 먼저 잘린다.

1. 임베딩 하이브리드 검색 (애초에 스트레치)
2. UI 폴리시 — 스트리밍 애니메이션, 다크모드
3. 대화 히스토리 멀티턴 (단일 턴으로 축소)
4. 근거 패널 접이식 → 항상 펼침으로 단순화

**절대 안 자르는 것:** 온프레미스 설계 문서, RBAC 필터, 인용, 거부 임계값, 배포. 이 다섯 개가 제출물의 논지 전체다.
